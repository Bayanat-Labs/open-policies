# Contributing

Thank you for reading the Bayanat Labs open policies. Issues are welcome.

## Issues

Open an issue for:

- an error, an unclear rule or a broken link;
- a licence, terms page or statute cited in these files that has changed since it was checked;
- a check in `manual/stages.yaml` or `manual/dod.yaml` that cannot pass or cannot fail;
- a bug in `bl-score`, the validators or the tests.

Say which file and version you read, and what you expected.

## Corrections and takedowns

To correct something about you or your work, or to ask for content to be removed from a Bayanat Labs release, write to **hello@bayanatlabs.com**. Do not put personal data in a public issue. We remove content within 30 days, and within 24 hours for requests from a platform. Each request is logged, and the corrected release gets a new version.

## Changes

Pull requests are welcome for typos, broken links and tests. Changes to a rule, a threshold, a tier or the licence matrix are made by Bayanat Labs: open an issue first. Thresholds and stage definitions change only with Bayanat Labs approval and a changelog entry (`policy/CHANGELOG.md`, `manual/CHANGELOG.md`). The English text governs where the English and Arabic editions differ.

Before you open a pull request, run the checks in the README. All must pass, including `python scripts/public_leak_check.py`.

By contributing, you agree that your contribution is licensed under the licence of the file you change (see `LICENSE.md`).

Documentation, not legal advice.
